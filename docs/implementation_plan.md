## 5. 报告写作方法

### 5.1 操作方式

1. 用编辑器打开 `report/report.html`，搜索 `class="todo"`，按 1.1 → 7 的顺序替换。
2. 每节先写 3–5 句结论，再补 1 个代码/表格证据；不要复述模板提示。
3. 每完成一章，浏览器打印预览一次，检查是否出现孤页、图注错位。
4. 提交信息建议：`docs(report): 完成第 1-2 章`、`docs(report): 完成第 3-4 章`。

### 5.2 字数预算（合计约 4,300 字）

| 小节 | 字数 | 写作重点 |
|---|---:|---|
| 1.1 项目与目标 | 250 | 为什么选二手交易；PA1 的四个问题；PA3 目标 |
| 1.4 与实验二差异 | 200 | 换 Python/SQLite 的理由；哪些设计被保留 |
| 2.1 转换方法 | 300 | 类图→实体、状态图→状态机、时序图→服务 |
| 2.3 类图→实体/仓储 | 250 | dataclass、枚举、SQL 只在仓储层 |
| 2.4 状态图→状态机 | 250 | 允许/禁止转换；改价重审；终态 |
| 2.5 时序图→创建预约 | 300 | 事务、幂等、60 秒、乐观锁 |
| 2.6 代码规模 | 120 | 3503 行口径；超过 1500 |
| 3.1 分层结构 | 180 | 路由/服务/仓储/领域职责 |
| 3.2 并发与幂等 | 220 | BEGIN IMMEDIATE + 唯一索引 + version |
| 3.3 事务与一致性 | 180 | 违规下架两条日志同事务 |
| 3.5 页面与交互 | 200 | 状态徽章、表单错误、窄屏 |
| 4.1 使用方式 | 250 | 给上下文、拆任务、先计划后代码 |

### 5.3 三条硬规则

- 不编造数据：所有数字以 `docs/` 为准。
- 不写“AI 帮我写完”：只写你实际让模型做的事和你的修改。
- 报告正文自己写；助手只做结构、排版、事实一致性检查。
